# 分支管理规则

## 允许的分支

本项目仅允许以下两个分支存在：

- `main` — 稳定版本分支，存放已发布的生产代码
- `dev` — 活跃开发分支，所有开发工作在此进行

## 禁止的分支

除 `main` 和 `dev` 以外的任何分支均被禁止，包括但不限于：
- `feature/*`
- `fix/*`
- `release/*`
- `hotfix/*`
- `trae/*`
- 任何其他自定义分支

## 工作分支

- **所有开发工作必须在 `dev` 分支上进行。**
- 当前工作分支：`dev`

## 分支创建规则

- **严禁私自创建任何新分支**进行开发任务。
- 如需创建新分支，必须经过明确授权。
- 项目仓库中只允许存在 `main` 和 `dev` 两个分支。

## 工作流程

1. 所有代码修改、功能开发、bug 修复都必须基于 `dev` 分支。
2. 提交前确保在 `dev` 分支上工作。
3. 禁止切换到其他分支或创建新分支进行开发。
4. 发布时从 `dev` 合并到 `main`，创建 Tag 和 Release。

## 违规处理

任何未经授权创建的分支将被视为违规，AI Agent 必须主动执行以下清理操作：

1. 删除本地多余分支：`git branch -D <branch>`
2. 删除远程多余分支：`git push origin --delete <branch>`
3. 切回 `dev` 分支继续工作

此规则为强制执行规则，AI Agent 不得以任何理由跳过或延迟执行。发现多余分支时必须立即清理，无需等待用户确认。
